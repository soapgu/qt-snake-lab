# 贪吃蛇交互原型说明

## 1. 定位与打开方式

本原型用于阶段 1 的界面、操作和反馈评审，使用独立 JavaScript 提供可试玩的经典贪吃蛇。后续 Qt/QML 程序、C++ 规则核心和 MVVM 展示层尚未实现，原型代码不作为 Qt 业务代码直接迁移。

直接打开 [离线原型](../prototype/index.html) 即可使用，无需安装依赖、运行构建或连接网络。样式与脚本均为本地相对引用，系统字体和 Canvas/CSS 承担绘制，无外部图片、字体、CDN 或网络请求。

当前状态为**交互原型评审通过**。软件实现方案和源码结构设计属于后续阶段，原型检查通过不代表 Qt 或麒麟实机验收已经通过。

## 2. 页面结构与操作条件

界面采用现代简洁街机风：深色背景、绿色蛇身、橙色食物、清晰棋盘网格和中文桌面操作控件。蛇头使用更亮的颜色并显示眼睛，状态也以文字表达。

| 页面或状态 | 展示与操作 | 条件和反馈 |
| --- | --- | --- |
| 首页 | 难度、对应最高分、操作说明、开始游戏 | 难度只在首页选择；开始后创建长度为 3、分数为 0 的新游戏 |
| 游戏进行中 | 棋盘、本局分数、最高分、蛇长、难度及移动间隔 | 方向键或 WASD 转向；可暂停、请求重开或返回首页 |
| 暂停覆盖层 | 保留棋盘，显示暂停原因 | 继续、重开、返回首页；计时停止，继续重新等待完整间隔 |
| 失败结算 | 失败原因、本局分数和最高分 | 暂停按钮禁用；再玩一次或返回首页，无需放弃进度确认 |
| 胜利结算 | 满格胜利、本局分数和最高分 | 再玩一次或返回首页；不再生成食物 |
| 重开或返回确认 | 说明本局进度不会保留 | 未结束的游戏先暂停；确认执行操作，取消保持暂停 |

首页与游戏页是页面导航，暂停和结算覆盖层是游戏状态展示。应用只维护一份游戏状态，不因覆盖层创建另一条蛇或第二个计时器。

在宽桌面窗口中，游戏棋盘和统计操作区左右排列。较窄窗口中调整间距，宽度小于 700 像素时改为上下排列；必要时允许页面纵向滚动，关键操作不隐藏。窗口缩放不改变 20 × 20 的逻辑棋盘。

## 3. 试玩规则、键盘与状态

| 规则 | 原型行为 |
| --- | --- |
| 初始化 | 棋盘 20 × 20，蛇长 3，蛇头从第 11 行第 11 列开始向右移动 |
| 难度 | 默认普通；简单 240 ms、普通 160 ms、困难 100 ms，每局间隔固定 |
| 食物 | 一个食物，随机选择空格；吃到后增长一格并加 10 分 |
| 转向 | 禁止直接反向，每周期只接受第一次有效转向；同方向和无效请求不占用机会 |
| 碰撞 | 撞墙或撞身体结束，棋盘保留最后合法位置 |
| 尾格 | 未增长时允许进入本步腾出的尾格，增长时尾部仍属于身体 |
| 胜利 | 蛇填满 400 格后胜利，最高可能分数为 3970 |
| 计时 | 每次只走一步，不追赶延迟；暂停和终局停止计时 |

正常状态转换为：准备 → 运行 → 暂停 → 运行，或运行 → 失败 / 胜利。返回首页清理本局；重开和再玩一次创建新游戏。

- 方向键及 WASD 转向，空格暂停或继续，Esc 在运行时暂停。
- 忽略按键自动重复，游戏键不会因长按带动页面滚动。
- 游戏开始和继续后焦点回到棋盘；鼠标点击棋盘也可恢复输入焦点。
- 按钮获得焦点时，空格使用按钮原生操作，不同时触发游戏快捷键；Esc 在运行时仍可暂停。
- 确认弹窗期间隔离转向及暂停快捷键。弹窗初始焦点为取消，Tab 和 Shift+Tab 在两个操作按钮之间循环，Esc 等同取消。
- 取消确认后焦点回到继续按钮，游戏保持暂停；确认重开后焦点回到新棋盘，确认返回后焦点回到首页开始按钮。
- 窗口失焦或页面转入后台自动暂停，恢复焦点或前台不自动继续。失焦暂停不抢夺用户当前焦点。
- 暂停及结算覆盖层显示文字说明；棋盘的无障碍名称提供分数、蛇长、蛇头和食物的位置。

## 4. 最高分、存储与评审工具

原型使用 localStorage 的独立键 qt-snake-lab.prototype.v1 保存所选难度与三档最高分。只在真实游戏结算时更新相应难度的最高分；重开或放弃未结束的本局不结算。

存储缺失时使用默认值；无效难度或分数使用默认值，分数要求为 0 至 3970 的 10 分倍数。读取、解析或写入失败显示提示，内存数据仍可使用。成功的后续保存写入当前内存记录并清除失败提示。

离线文件和本机 HTTP 预览具有不同的存储环境，记录不保证互通。直接打开文件时的存储是否可用由浏览器环境决定，失败会降级为当前页面的内存记录，不声称已经保存。

页面底部的“原型评审工具”默认折叠：

| 操作 | 效果 | 数据边界 |
| --- | --- | --- |
| 查看失败示例 | 载入撞身体结算，示例分数为 140、蛇长 17 | 明确显示评审示例，不写入最高分 |
| 查看胜利示例 | 载入满格胜利，示例分数为 3970、蛇长 400 | 明确显示评审示例，不写入最高分 |
| 模拟一次保存失败 | 发起一次模拟失败的保存，展示内存降级提示；运行中的游戏暂停 | 不删除已有记录，下一次正常保存可恢复 |

载入结算示例会替换当前试玩棋盘。示例中的“再玩一次”启动正常的新游戏，后续正常试玩可以保存成绩。评审工具只用于检查少见状态，不属于后续 Qt 游戏必需的产品界面。

## 5. 推荐评审路径

1. 打开首页，确认普通为首次默认难度。依次选择三档难度，核对最高分与间隔文案。
2. 用简单难度开始，使用方向键或 WASD 接近食物。吃到后核对分数增加 10、蛇长增加 1。
3. 连续请求两次转向或直接反向，核对同一周期不会二次转向、不会直接掉头。长按方向键不应重复转向或滚动页面。
4. 空格暂停，等待数秒，确认棋盘不动；空格或继续按钮恢复，不应立即补走多步。
5. 点击重开，检查初始焦点、Tab 循环和方向键隔离。取消后保持暂停；再次重开并确认，核对分数归零和蛇长为 3。
6. 未结束时返回首页，先取消再确认，核对暂停、导航和焦点恢复。
7. 实际撞墙或撞身体，查看结束原因与计分；再玩一次或直接返回首页。取得最高分后刷新，检查对应难度记录恢复及其他难度独立。
8. 把浏览器窗口切换到其他窗口或后台，核对自动暂停；回来后应保持暂停，主动继续才恢复。
9. 展开评审工具，分别查看失败和胜利示例，确认模拟标签、分数、蛇长和按钮；回首页或刷新后真实最高分不变。
10. 模拟一次保存失败，确认提示明确且仍可游戏；回首页变更难度，检查后续正常保存能清除提示。
11. 在 800 × 600 和 1280 × 800 窗口检查首页、棋盘、暂停、结算和确认弹窗。小窗口可以纵向滚动，不应出现横向溢出或操作被覆盖。
